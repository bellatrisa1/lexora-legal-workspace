## Что проверялось поведением

- Переключение English, Русский, Español, Français и Italiano, сохранение cookie и определение языка на сервере.
- Английский fallback для неподдерживаемого языка браузера.
- Сохранение черновика формы при смене языка и перевод уже показанных ошибок валидации.
- Независимость языка, юрисдикции и часового пояса; неизменность пользовательского контента.
- Поиск, фильтры, создание дел, сообщения, статусы, документы, задачи, демороли и восстановление после ошибки API.
- Повторное применение миграций и seed без дублирования записей.
- Проверка входных данных, внешних ключей и ограничений возможностей деморолей на сервере.
- Параллельные изменения статуса и связанные записи истории.
- Сохранение дела, сообщения и статуса в PostgreSQL после перезагрузки страницы и через новое соединение с базой.

База для проверки — отдельный временный кластер PostgreSQL 17 на loopback-порту `55439`. Интеграционные тесты создавали собственную схему и удаляли её после выполнения. REST E2E создавали вымышленные дела только в тестовой базе. Пользовательские настройки подключения и существующие базы не изменялись.

## Оставшиеся ограничения

Полный `npm audit`, включая dev-зависимости, сообщает о пяти high-записях в цепочке `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`. Предложенный npm автоматический вариант требует отката `eslint-config-next` до `14.2.35`, поэтому `npm audit fix --force` не применялся. Это остаётся задачей обновления инструментария; чистый runtime-аудит не означает, что все зависимости проекта свободны от предупреждений.

Сборка frontend в production-режиме **не означает готовность всей системы к публичному размещению**. Express API запускается только в явно включённом локальном деморежиме. Демозаголовки личности не являются аутентификацией. Настоящие сессии, серверный RBAC и безопасная изоляция организаций — следующий этап.

Для воспроизведения команд и настройки собственной базы см. [README](../README.md).
